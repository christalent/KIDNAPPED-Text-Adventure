# FLOOR 7 AUDIT — 2026-11-05

Ground truth for Floor 7 of *Kidnapped!* (Peter Kirsch, SoftSide).
Primary source: `KIDNAPPED_Original.pdf` (Dec-1980 issue), read from the
**native 300 ppi page bitmap** (pixel crops under
`/home/chris/.hermes/cache/scratch/kidnap_audit/`), not from the PDF text
layer and not from `KIDNAPPED_OCR.txt`.
`KIDNAPPED_OCR.txt` is used only as a search aid; where OCR and pixels
disagree, the pixels win.

## 0. Status of the previous `floors/floor_7.py`

The previous module was **wrong and was never source-audited**. It claimed
Floor 7 = "The Bank Vault", global rooms **31-39 + 55-56**, with a
`BALL OF YARN` / `KNITTING NEEDLES` / burglar / `DOLLAR BILL` puzzle.
That geography does not exist in the listing:

* global rooms 31-36 are **Floor 6** (audited separately — vault, kidnapper,
  helium tank, balloon, gun, ransom dollar);
* rooms 55-56 are the lowest floors (alligator / entrance hall area);
* rooms 18-25 — the real Floor 7 — were **absent** from the module.

The yarn/knitting-needs/burglar puzzle is the **Floor 5** puzzle (press the
button, knit clothes) and the `DOLLAR BILL` is the **Floor 6** ransom
dollar. The old module was a fabrication that collided with two other
floors. It has been replaced.

## 1. Why rooms 18-25 are Floor 7

The listing's room table is a single `ON A GOTO` dispatch (listing line 10)
covering rooms 1-65. Global room number = listing line - 10, and each
floor occupies a contiguous block of lines:

| floor | listing lines | global rooms |
|-------|---------------|--------------|
| 9     | 11-21        | 1-11   |
| 8     | 22-27        | 12-17  |
| **7** | **28-35**    | **18-25** |
| 6     | 36-46        | 26-36  |

Floor 8 was confirmed independently by `FLOOR9_AUDIT_2026-11-03.md`
(rooms 13-17), and Floor 6 by `audit/FLOOR6_VERBATIM.md` (rooms 26-36);
those two blocks bracket the lines 28-35 block and leave it as Floor 7.

### OCR trap (the "4 reads as 1" corruption)

The OCR text layer and `KIDNAPPED_OCR.txt` render every printed **4** as
**1** on this page. So the text layer shows `E=21` on line 28 and `W=21`
on line 35 where the pixels show `E=24` and `W=24`. The pixels are
right, and they are self-proving:

* room 18 `E=24` <-> room 24 `W=18`  (reciprocal)
* room 25 `W=24` <-> room 24 (the locked door is passed with `GO DOOR`,
  not by a direction; that is why 24 lists no E and 25 lists no E)
* room 18 `W=20` <-> room 20 `E=18`;  `N=19` <-> room 19 `S=18`;
  `S=21` <-> room 21 `N=18`;  room 21 `E=22` <-> room 22 `W=21`;
  room 22 `E=23` <-> room 23 `W=22`.

Every directed edge in the table is reciprocal except the door edge
24 -> 25, which the walkthroughs pass with `GO DOOR`.

## 4. Handler code (listing lines 900-950)

```
900 IF D(B)<>11 THEN 930 ELSE IF A=19 IF E$="KEY" IF I(21)=1 A$(56)="CRUDE KEY":...
930 IF D(B)<>12 THEN 950 ELSE IF A=25 IF I(19)=1 IF I(20)=1 ... IF E$="STEP" ... PRINT "STAIR'S FIXED":SC=1:...GOTO5000
950 IF D(B)<>13 THEN 960 ELSE IF I(25)=1 IF I(24)=1 ... IF E$="DOWN" K3=25:R$="":...GOTO5000
975 IF SP=0 THEN 1000 ELSE IF A=19 THEN A=18:GOTO300 ELSE IF A=18 IF BR=0 THEN ...
```

* **line 900** — `MAKE KEY` at room 19 (the key making machine). Requires
  the copper sheet (`I(21)=1`) and yields item 56, `CRUDE KEY`.
* **line 930** — at room 25 (narrow stairway) `GLUE STEP` fixes the
  staircase: needs the wooden stair step and the super glue, prints
  `STAIR'S FIXED`, sets flag `SC=1`.
* **line 950** — `GO STAIRS` / `GO DOWN` from room 25 descends to the next
  floor once the stairs are fixed.
* **line 975** — after using the machine, control returns to room 18.

## 6. Still open / ambiguities

1. **`J$` / `N$` text for Floor 7** — the two generic descriptions used
   by rooms 18, 19, 21, 22, 24 are set by the floor's init line
   (the same mechanism that sets `J$="IN A HALLWAY.":N$="IN AN OFFICE."`
   for Floor 9, listing line ~220). The init line for `FL=7` still has to
   be read from pixels before the generic room names are final.
2. **DATA line 2010** — the printed item names and their signs have been
   read from the OCR, but the pixel pass on the DATA block
   (`F7_DATA.png`) is still being confirmed; the item *rooms* above are
   corroborated by the walkthroughs, so only the exact spelling/sign of
   each DATA entry remains to be locked.
3. **Room 19 and room 22 are both `N$`** — they are the same generic
   description but hold different contents (19 = key making machine),
   so the generic text must not be treated as a full room description.

### Handler line 900 - MAKE KEY

    900 IF D(B)<>11 THEN 930 ELSE IF A=19 IF E$="KEY" IF I(21)=1
        A$(56)="CRUDE KEY":H$(56)=A$(56):A(56)=19:GOTO4900

`A(56)=19` places the new CRUDE KEY in room 19, i.e. the office with the
key-making machine, so it is picked up in the same room it is made.

Two conflicting digit reads came back from zoom-only crops of the right
half of row 900 (one said 15, one said 21).  Both are wrong: the wrapped
continuation row of the listing reads `KEY":H$(56)=A$(56):A(56)=19:GOT04900`
and the published walkthrough makes the key and picks it up with no
movement in between (MAKE KEY / GET CRUDE KEY), which is only possible if
the key is in room 19.  Room 19 it is.

### Handler line 930 - GLUE STEP

    930 IF D(B)<>12 THEN 950 ELSE IF A=25 IF I(19)=1 IF I(20)=1 OR I(20)=A
        IF E$="TEP" OR E$="IRS" PRINT"STAIR'S FIXED":SC=1:RS="":K3=20:GOSUB1100

Room 25 only: SUPER GLUE (19) plus WOODEN STAIR STEP (20), which is
consumed (K3=20).  Sets the stairway-fixed flag.  E$="TEP" and E$="IRS"
are the three-letter matches for STEP and STAIRS.
